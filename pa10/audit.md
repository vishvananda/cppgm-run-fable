# PA10 Audit

## Audit Plan

Scope: commit a1198a821 (`Implement PA10 emit-ast`) plus the PA9 timeout fix
dbf6e3843 that landed after it. Baseline: 518/518 tests green through PA10,
file audit clean.

### Files to inspect

- `dev/cppgm++.cpp` — driver surface: `--emit-ast` wiring, error paths,
  no fallback success, unimplemented modes still throw for PA11+.
- `dev/src/ast/ast.h`, `ast.cpp`, `ast_expr.h`, `ast_names.h` — data model:
  structured (not stringly) names/types/expressions, ownership via
  `unique_ptr`, no parser/printer knowledge leaking in.
- `dev/src/ast/ast_parser.h`, `ast_parser_core.cpp` — token infrastructure,
  save/restore, bracket stack, name table + undo log.
- `dev/src/ast/ast_parse_{names,expr,stmt,decl,declarator,class}.cpp` —
  grammar coverage vs `pa10.gram`, disambiguation rules, backtracking
  correctness and cost.
- `dev/src/ast/ast_printer.cpp`, `ast_text.cpp` — deterministic dump,
  fixture vocabulary, no parsing of rendered text back.
- `dev/frontend_source_sets.mk` — build wiring, no source dropped from the
  audit path.
- `pa10/` handout files — confirm no tests, refs, scripts, or grammar files
  were edited.

### Cheating / shortcut checks

- Grep parser+printer for fixture-specific identifiers, file names, token
  counts, or source-shape probes (accepting input only when it looks like a
  specific test).
- Confirm failures come from real parse rejection, not an exit-status table.
- Confirm the dump is generated from typed AST nodes, not embedded reference
  text or earlier-IR payloads.
- Confirm `recog` (PA6) and the PA1-PA9 pipeline are untouched apart from
  shared-file build wiring; diff against the pre-PA10 commit.

### Performance risks

- Ordered-choice backtracking with no memoization: look for re-parse hot
  spots (declaration-vs-expression, type-id-vs-expression in template
  arguments, parameter abstract/named double parse) and any input shape that
  goes super-linear; check whether undo log and bracket stack restore in
  O(parse length).
- Name-table lookups: per-scope `std::map` walk per identifier; check no
  full-table or full-token rescans on hot paths.
- Printer/ast_text: check for repeated flattening of the same subtree or
  string concatenation in loops without reserve (acceptable at fixture
  scale, flag if quadratic).

### Ownership boundaries

- Parser owns syntactic classification (name table); AST owns structure;
  `ast_text` owns one-line spellings; printer owns indentation/vocabulary.
  Look for duplicated rendering logic between `ast_text` and `ast_printer`,
  semantic facts stored as strings the AST should structure (lambda
  introducer, attribute text), and downstream re-derivation of facts the
  parser already had.

### File-audit issues

- All sources well under the 1500-line gate; verify no function exceeds 120
  lines and no implementation hides in headers or unchecked paths to dodge
  the audit (`ast_expr.h`, `ast_names.h` are header-only by design — confirm
  they hold data definitions, not moved logic).

## Findings

Verified clean (no action needed):

- No cheating vectors: no fixture names, test-shape probes, exit-status
  tables, embedded reference text, or dummy outputs anywhere in
  `dev/src/ast/` or the driver. The dump is generated by walking the
  typed AST; failure exits come from real parse rejection
  (`ParseTranslationUnit` throws unless the whole token sequence
  matches and ends at ST_EOF).
- No regressions: `recog` (PA6) and the PA1-PA9 pipeline are untouched;
  the only shared-file change is `dev/frontend_source_sets.mk` adding
  the cppgm++ object list. The post-PA10 commit dbf6e3843 is a genuine
  PA9 algorithmic fix (cache-line isolation + tighter codegen,
  8.8s -> 0.30s), not a timeout workaround.
- Handout integrity: `pa10/tests`, `pa10/scripts`, `pa10.gram`, and the
  grammar explorer have no commits since the assignment export.
- Build wiring: every `dev/src/ast/*.cpp` is in
  `FRONTEND_OBJ_BASENAMES_cppgm++`, all inside the audited
  `dev/src` path. No hidden or unchecked implementation fragments.
- `Restore` cannot re-push brackets popped below the save depth;
  audited every Save/Restore site: each parse function only consumes
  closers for brackets it opened itself, so the truncate-only restore
  is sound.
- The reference accepts a superset of `pa10.gram` (`sizeof...(pack)`,
  capture-defaults in non-leading position). The grammar is the
  contract; behavior outside it is undefined, so the parser stays
  grammar-faithful. All fixture-pinned behaviors match.

Fixed during this audit:

1. Stringly lambda captures (ownership + downstream-recovery). The
   parser flattened the lambda-introducer to a `"[&x,=]"` string inside
   `ParseLambdaIntroducer`, putting rendering logic in the parser and
   forcing PA11/PA12 to reparse capture text. The grammar defines
   structured captures (capture-default, capture-list with `id`, `&id`,
   `this`, packs).
2. Exponential template-argument re-parsing (performance). Each
   ordered-choice alternative re-parsed nested template-argument clause
   spans from scratch: type-id-versus-expression at every argument and
   uncommitted `name<` attempts compounded as 2^depth.
   `a<a<...<1+0>+0>+0>` at depth 12 exceeded 10s (the reference
   rejects any depth in ~0.5s); both implementations agree on the
   verdict (reject), mine just burned exponential time reaching it.
3. Stringly keyword comparison (minor): the printer tested
   `spec.spelling == "explicit"` instead of the token kind.
4. Documentation gap: non-type template parameters are a
   fixture-required extension beyond `source.gram` (which derives
   template-parameter from type-parameter only) but were missing from
   the plan's extension list.

Pre-existing, out of PA10 scope: the file audit's one warning
(`dev/src/parse/parser.h` header-implementation division) is the PA6
recognizer's structure, untouched by PA10 and accepted by the audit
script since PA6.

## Changes Made

- `dev/src/ast/ast_expr.h`, `ast.cpp`: `AstLambdaCapture`
  (`LC_THIS`/`LC_COPY`/`LC_REF`, identifier, pack flag) and
  `AstLambda.has_capture_default`/`capture_default`/`captures` replace
  the flattened `introducer` string.
- `dev/src/ast/ast_parse_expr.cpp`: `ParseLambdaIntroducer` builds the
  structured captures following the grammar (capture-default only in
  leading position; lone `&` not followed by an identifier is the
  by-reference default).
- `dev/src/ast/ast_text.{h,cpp}`: `FlattenLambdaIntroducer` renders the
  dump's `[...]` text from the structure; `ast_printer.cpp` and
  `FlattenExpr(EK_LAMBDA)` use it. Rendering now lives only in
  `ast_text`, byte-identical to the reference for every capture form.
- `dev/src/ast/ast_parser.{h,cpp-files}`: `clause_memo_` maps `<` token
  positions to template-argument-clause attempt outcomes
  (success + end position, or failure). Recorded in
  `ParseTemplateArgumentClause`; consulted there (failure
  short-circuit) and at the two uncommitted-attempt sites
  (`ParseTerminalIdentifier` expression-context `(`-follow check,
  `ParseNestedNameParts` `::`-follow check), which skip re-parsing when
  the memo already answers the commit test. Invalidated on every name
  registration, undo rollback, and scope push/pop — the only state a
  clause parse depends on besides the tokens.
- `dev/src/ast/ast_printer.cpp`: `spec.keyword == KW_EXPLICIT` replaces
  the spelling comparison.
- `cppgm.tests/course/pa10/lambda-captures.t` + `.ref` +
  `.ref.exit_status`: course fixture covering every grammar capture
  form (`[]`, `[&]`, `[=]`, `[this]`, `[x]`, `[&x]`, `[x,&y]`,
  `[=,&x]`, `[&,y]`, `[args...]`, `[&,args...]`); ref pinned from the
  reference binary via the harness
  (`CPPGM_APP_ARGS=--emit-ast scripts/run_all_tests.pl ./cppgm++-ref
  ref course/pa10`).
- `pa10/plan.md`: clause-memo description, non-type-template-parameter
  extension note, course fixture in Validation, and the Architecture
  Review / Final Architecture Review sections.

## Validation

- `make -C pa10 test`: 134/134 local + 1/1 course.
- Root `make test-report-through-pa10`: 519/519
  (was 518 before the course fixture; PA1-PA9 all green).
- `perl scripts/cppgm_file_audit.pl --stage pa10 --paths dev/src`:
  passed (1 pre-existing PA6 warning, see Findings).
- Differential checks against the reference binary: lambda capture
  forms, pack captures, and a template-heavy disambiguation input all
  byte-identical; adversarial nesting verdicts agree (EXIT_FAILURE).
- Performance: 22k-line mixed input parses in ~0.73s with byte-identical
  output before/after the memo; `a<a<...>+0>` adversarial nesting went
  from >10s at depth 12 (2^depth) to instant rejection at depth 24.
